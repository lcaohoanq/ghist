## Build flow

- `render.py` from the frontdoor-illustrate skill serves `assets/` over HTTP, opens `figures.html?theme=light|dark` in Edge or Chrome, screenshots each `.item` at 2x, rounds and borders it, and writes lossless WebP named after the item id (`<id>.webp`, `<id>-dark.webp`).
- The exact command is in the header comment of `figures.html`; it runs through `uvx` with Playwright and Pillow, with no admin rights.
- After rendering, `hero-dark.webp` is re-encoded lossy at quality 94 (RV-D7 in `hallucination`); the command is in the same header comment.
- `render.py --items renames,readonly,reviews,layers` renders a subset, which leaves the lossy `hero-dark.webp` untouched.
- `render.py` exits 1 on a WARN: content outside an item, a file over 300 KB, a font that did not load, or a starter placeholder still served. The hero bleeds by design, so its window sits in an element marked `data-bleed`.

## Data in the pictures

- `COMMITS`, `DIFF` and `FILE` in `figures.html` are copied from `git log --follow` and the diff of `34fd8a5` for `internal/hosting/hosting.go`; they are not regenerated by any script.
- Terminal text is word-wrapped with the continuation mark the real interface draws.
- The workflow cards crop the same data to fit.
- `renames` uses made-up names and commit ids written in the script (RV-D12); `readonly`, `reviews` and `layers` carry text only, each statement traced to `internal/git`, `internal/hosting/hosting.go`, package imports or `docs/plan.md` (RV-D13, RV-D14).
